# Pairdraw и Penpot: архитектура и производительность

Зачем сравнивать? Pairdraw существует потому, что закрытые платформы дизайна определяют, что возможно, а что нет. Разница в архитектуре показывает, что открытая альтернатива с локальным хранением может сделать иначе.

::: info WASM-рендерер Penpot
Penpot 2.x включает Rust/Skia WASM-рендерер `render-wasm/v1`, который включается параметрами сервера или `?wasm=true`. По умолчанию по-прежнему используется SVG-рендерер. Ниже рассматриваются оба варианта.
:::

## 1. Размер кодовой базы

| Показатель      | Pairdraw                                                                         | Penpot                                              |
| --------------- | -------------------------------------------------------------------------------- | --------------------------------------------------- |
| Строк кода      | **около 437 000**                                                                | **около 299 000**                                   |
| Исходных файлов | около 4 200                                                                      | около 2 900                                         |
| Языки           | TypeScript, Vue, Rust                                                            | Clojure, ClojureScript, Rust, JavaScript, SQL, SCSS |
| Код отрисовки   | около 2 500 строк (TypeScript, 14 файлов в `packages/core/src/canvas/renderer/`) | 22 000 строк (Rust/Skia WASM)                       |
| Интерфейс       | около 173 000 строк (`src/`)                                                     | около 175 000 строк (CLJS и SCSS)                   |
| Серверная часть | Необязательный сервер Cloud (TypeScript)                                         | 32 600 строк и 151 файл SQL                         |
| Соотношение     | **1,5×**                                                                         | **1×**                                              |

Клиент Pairdraw сопоставим по размеру с клиентом Penpot и вмещает весь редактор в один процесс: без базы данных, без флота сервисов и с необязательным бэкендом для команд, которым он нужен.

## 2. Архитектура

### Pairdraw: монолитный клиент

```
┌─────────────────────────────────┐
│         Tauri (native shell)    │
│  ┌───────────────────────────┐  │
│  │  Vue 3 + TypeScript       │  │
│  │  ┌─────────┐ ┌──────────┐│  │
│  │  │  Editor  │ │  Kiwi    ││  │
│  │  │  Store   │ │  Codec   ││  │
│  │  └────┬─────┘ └──────────┘│  │
│  │       │                    │  │
│  │  ┌────▼────────────────┐  │  │
│  │  │  Scene Graph (TS)    │  │  │
│  │  │  Map<string, Node>   │  │  │
│  │  └────┬────────────────┘  │  │
│  │       │                    │  │
│  │  ┌────▼────┐ ┌──────────┐│  │
│  │  │  Skia   │ │  Yoga    ││  │
│  │  │CanvasKit│ │  Layout  ││  │
│  │  │  (WASM) │ │  (WASM)  ││  │
│  │  └─────────┘ └──────────┘│  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

**Всё в одном процессе.** Ни сервера, ни базы данных, ни Docker. SceneGraph — плоская `Map<string, SceneNode>` в TypeScript. Отрисовка напрямую вызывает Skia CanvasKit из TypeScript, а компоновку синхронно рассчитывает Yoga WASM.

### Penpot: распределённая клиент-серверная система

```
┌───────────────────────────────────────────────────────┐
│                    Docker Compose                      │
│  ┌──────────────┐  ┌─────────────┐  ┌──────────────┐ │
│  │   Frontend    │  │   Backend   │  │   Exporter   │ │
│  │  ClojureScript│  │   Clojure   │  │  (Chromium)  │ │
│  │  shadow-cljs  │  │   JVM       │  │              │ │
│  │  ┌─────────┐ │  │  ┌────────┐ │  └──────────────┘ │
│  │  │render-  │ │  │  │Postgres│ │                    │
│  │  │wasm     │ │  │  │Valkey  │ │  ┌──────────────┐ │
│  │  │(Rust→   │ │  │  │ MinIO  │ │  │   MCP        │ │
│  │  │ Skia    │ │  │  └────────┘ │  │   Server     │ │
│  │  │ WASM)   │ │  │             │  └──────────────┘ │
│  │  └─────────┘ │  │             │                    │
│  └──────────────┘  └─────────────┘                    │
└───────────────────────────────────────────────────────┘
```

**Минимум пять служб.** PostgreSQL для хранения, Redis (Valkey) для pub/sub и кеширования, MinIO для ресурсов, серверная часть на JVM, экспортёр на Node.js (Chromium без интерфейса для отрисовки на сервере) и интерфейс на ClojureScript. Среда разработки требует Docker Compose с собственной настройкой сети.

### Вывод: архитектура

Архитектура Pairdraw в одном процессе устраняет:

- сетевую задержку между интерфейсом и серверной частью;
- затраты на сериализацию и десериализацию на границах служб;
- сложность управления контейнерами;
- запросы к базе данных при каждой операции.

Архитектура Penpot оптимизирована для **многопользовательских развёртываний на сервере**. Pairdraw оптимизирован для **мгновенной локальной работы**.

## 3. Конвейер отрисовки

### Pairdraw: TypeScript → CanvasKit WASM (напрямую)

```typescript
// renderer.ts — direct CanvasKit calls from TypeScript
renderSceneToCanvas(canvas, graph, pageId) {
  // Iterate nodes, build Skia paths/paints, draw
  this.fillPaint.setColor(...)
  canvas.drawRRect(rrect, this.fillPaint)
}
```

- **Один переход границы:** TypeScript → WASM (CanvasKit).
- SceneGraph остаётся в памяти JavaScript и не сериализуется перед отрисовкой.
- Код отрисовки занимает около 2 500 строк и разделён на специализированные модули в `packages/core/src/canvas/renderer/`

### Penpot: JavaScript (скомпилированный из CLJS) → Rust WASM → Skia

Penpot 2.x включает Rust/Skia WASM-рендерер `render-wasm/v1`, который включается параметрами сервера или `?wasm=true`. В этом режиме фигуры отрисовываются так:

```
ClojureScript (compiled to JS)
  → decompose to primitives + binary-pack into WASM linear memory
  → Rust WASM (via Emscripten C FFI)
  → skia-safe (Rust Skia bindings)
  → Skia (WebGL)
```

Когда режим выключен (по умолчанию), фигуры отображаются как дерево SVG DOM через React/Reagent: каждая фигура — отдельный элемент DOM.

- **Один переход границы** (JavaScript → WASM), как у Pairdraw, но с явными затратами на сериализацию: UUID разбивается на четыре `u32`, преобразование — на шесть `f32`, заливки и обводки упаковываются в двоичном виде, а основные свойства каждой фигуры собираются в структуру размером 104 байта.
- Плиточная система отрисовки с областями интереса.
- 11 отдельных поверхностей отрисовки (заливки, обводки, тени и т. д.).
- Глобальное изменяемое состояние через шаблон `unsafe { STATE.as_mut() }`.
- Движок отрисовки на Rust объёмом 22 000 строк.

Плиточная система Penpot (`TileViewbox`, `TileTextureCache`, `TILE_SIZE_MULTIPLIER`) заранее отрисовывает плитки вокруг видимой области и кеширует текстуры (до 1024 записей).

Pairdraw перерисовывает всю видимую область в каждом кадре: CanvasKit, вызываемый напрямую из TypeScript, достаточно быстр, чтобы обходиться без плиток.

### Вывод: отрисовка

| Аспект                    | Pairdraw                        | Penpot                                                      |
| ------------------------- | ------------------------------- | ----------------------------------------------------------- |
| Граница JavaScript → WASM | Напрямую (объекты TypeScript)   | Двоичная упаковка (структура основных свойств на 104 байта) |
| Модель отрисовки          | Немедленная, полная перерисовка | Кеш плиток                                                  |
| Поверхности               | 1                               | 11                                                          |
| Затраты памяти            | Низкие (без кеша плиток)        | Высокие (кеш на 1024 плитки)                                |
| Сложность кода            | около 2 500 строк (14 файлов)   | 22 000 строк                                                |
| Небезопасный код          | Нет                             | Глобальное состояние через `unsafe`                         |

Когда WASM-рендерер Penpot включён, оба проекта используют Skia через переход JavaScript → WASM. Pairdraw вызывает CanvasKit напрямую с объектами TypeScript. Penpot раскладывает данные ClojureScript в двоичные структуры, записывает их в линейную память WASM и отрисовывает через движок на Rust объёмом 22 000 строк. Когда WASM выключен (по умолчанию), Penpot отображает фигуры как дерево SVG DOM. Для небольших и средних документов прямой путь через CanvasKit быстрее. Плиточная система Penpot может выиграть на очень больших холстах (100 000 фигур и более), когда видна лишь малая часть, но её накладные расходы значительны.

## 4. SceneGraph и модель данных

### **Pairdraw**

```typescript
// Flat map, O(1) lookup
nodes: Map<string, SceneNode>
// 64 node types in Figma's Kiwi schema; the engine builds 20
// NodeChange carries about 290 Figma-compatible fields
```

- Интерфейсы TypeScript со строгими типами.
- GUID в формате Figma `sessionID:localID`.
- Прямой доступ к свойствам, без промежуточных слоёв.

### Penpot

```clojure
;; 20+ type definition files in common/src/app/common/types/
;; shapes_builder.cljc, shapes_helpers.cljc
;; Separate type systems for: color, component, container, fills,
;; grid, modifiers, objects_map, page, path, etc.
```

- Данные распределены по `common/` (49 600 строк `.cljc`).
- Отдельные геометрические модули для Flex-компоновки (около 6 файлов), Grid-компоновки (около 5 файлов), ограничений, границ, углов и эффектов.
- Проверка схем во время выполнения (Malli).
- Для отрисовки данные должны пересечь границу CLJS → Rust.

### Вывод: модель данных

Pairdraw напрямую использует в TypeScript проверенную схему Figma (605 определения Kiwi) без какого-либо перевода. Penpot поддерживает собственную систему типов в Clojure, ClojureScript и Rust, и все три приходится синхронизировать вручную.

## 5. Движок компоновки

### Pairdraw: Yoga WASM (314 строк)

```typescript
import Yoga from 'yoga-layout'
// Direct mapping: Figma stack* fields → Yoga flex properties
const root = Yoga.Node.create()
root.setFlexDirection(FlexDirection.Row)
root.calculateLayout()
applyYogaLayout(graph, frame, yogaRoot)
```

Всего 314 строк. Синхронно, внутри процесса.

### Penpot: две реализации

1. **ClojureScript** (common): `flex_layout/` (6 файлов), `grid_layout/` (5+ файлов) — собственные реализации.
2. **Rust WASM**: `flex_layout.rs` (741 строка), `grid_layout.rs` (843 строки) — заново написанные с нуля.

Penpot поддерживает **два независимых движка компоновки** (CLJS и Rust), которые должны выдавать одинаковый результат.

### Вывод: компоновка

Pairdraw передаёт компоновку проверенной библиотеке (Yoga, которую React Native использует на миллиардах устройств) и обходится 314 строками. Penpot поддерживает более 3 000 строк собственного кода компоновки, продублированного на двух языках.

## 6. Формат файлов и совместимость с Figma

### **Pairdraw**

- **Нативный бинарный формат Kiwi** — та же сериализация, которую Figma использует внутри.
- Прямой импорт файлов `.fig` через кодек Kiwi (схема в `packages/kiwi/src/fig/schema/fig.kiwi`, кодирование в `codec.ts`).
- Вставка из буфера обмена Figma (Pairdraw читает бинарные данные Kiwi из буфера обмена).
- Кодек Kiwi охватывает схему сообщений многопользовательского протокола Figma (к серверам Figma Pairdraw не подключается).

### Penpot

- **ZIP-архив** (файлы `.penpot`) с манифестами JSON, данными каждого файла в JSON, бинарными ресурсами и миниатюрами (формат v3).
- SVG используется для отрисовки по умолчанию и для экспорта (WASM-рендерер включается отдельно).
- Нет нативного импорта `.fig`.
- Три версии формата (устаревший v1 на Transit, v2, v3 с JSON в ZIP) с системой миграций.

### Вывод: формат файлов

У Pairdraw здесь заметное преимущество: он нативно читает файлы Figma и даже принимает данные из буфера обмена Figma. В Penpot нужен ручной экспорт и импорт, а файлы `.fig` он открыть не может.

## 7. Состояние и отмена

### **Pairdraw**

```typescript
// Inverse-command pattern (`packages/scene-graph/src/undo.ts`)
class UndoManager {
  apply(entry: UndoEntry) {
    entry.forward()
    this.undoStack.push(entry)
  }
  undo() {
    entry.inverse()
    this.redoStack.push(entry)
  }
}
```

Замыкания применения и отмены сохраняют минимум состояния. Многошаговые операции можно объединять в пакеты.

### Penpot

Состоянием управляет Potok (библиотека в духе Redux для атомов ClojureScript). События реализуют `UpdateEvent` (чистая функция состояние → состояние) или `WatchEvent` (побочные эффекты через RxJS). История отмены хранит обратные векторы изменений (не более 50 записей), объединяет быстрые изменения в транзакции и сбрасывает их через 20 секунд.

### Вывод: состояние

Подход Pairdraw проще и требует меньше накладных расходов. Подход Penpot лучше подходит для совместной работы (изменения сериализуемы), но ценой сложности.

## 9. Производительность

Это различия в устройстве, а не замеры: редакторы не измерялись рядом друг с другом.

| Сценарий               | Pairdraw                                        | Penpot                                 |
| ---------------------- | ----------------------------------------------- | -------------------------------------- |
| Холодный запуск        | Загрузка модулей WASM                           | Запуск сервера, затем клиента и WASM   |
| Путь операции          | Внутри процесса                                 | Сетевой обмен с сервером               |
| Кадр                   | Прямой вызов Skia                               | CLJS → JS → WASM FFI → Skia            |
| Запущенные процессы    | Одна вкладка браузера или настольное приложение | JVM, Postgres, Valkey и браузер        |
| Работа без сети        | Полная (локальное хранение)                     | Нет (зависит от сервера)               |
| Отрисовка 10 000 фигур | Один проход, без кеширования                    | Плиточная отрисовка с 11 поверхностями |

## 10. В чём Penpot лучше

1. **Серверная совместная работа** — централизованное многопользовательское редактирование через WebSockets, учётные записи и контроль доступа, проверенные в масштабе (Pairdraw редактирует вместе только через необязательный собственный сервер Pairdraw Cloud, и одноранговых комнат у него нет).
2. **Система плагинов** — полноценный API плагинов с изолированным выполнением и экосистемой плагинов (плагины Pairdraw запускаются по одному и без доступа к сети).
3. **CSS Grid** — собственная реализация (Pairdraw использует ответвление Yoga с поддержкой Grid).
4. **Самостоятельное размещение** — развёртывание для команд через Docker (Pairdraw Cloud — один процесс Node, и он появился позже).
5. **Зрелость** — годы эксплуатации, проверка в масштабе.

## 11. Сценарии и расширяемость

В Pairdraw есть [команда `eval`](/ru/programmable/cli/scripting) с совместимым с Figma Plugin API для сценариев без интерфейса: пакетные операции, автоматизированное тестирование и изменения силами ИИ выполняются без графического интерфейса. Кроме того, **139 инструментов ИИ** доступны во встроенном чате, на сервере MCP (stdio и HTTP) и в CLI: чтение, создание, изменение, структура, переменные, векторные контуры, анализ (цвета, типографика, отступы, кластеры), сравнение, логические операции и расположение. У Penpot есть система плагинов с изолированным выполнением, но нет API для сценариев без интерфейса и интеграции MCP.

| **Зрелость экосистемы**           | Penpot       | Годы эксплуатации против ранней стадии                                                                                                                                  |

Архитектура Pairdraw компактнее: отрисовка через CanvasKit в одном процессе, TypeScript и совместимость с Figma по замыслу. Penpot — полноценная платформа примерно на 299 000 строк на Clojure, ClojureScript, Rust и SCSS с набором служб Docker. Оба предлагают совместную работу в реальном времени через сервер, а в Pairdraw он необязателен. У Penpot есть экосистема плагинов; у **Pairdraw** — совместимые с Figma сценарии без интерфейса, **139 инструментов ИИ и MCP**, экспорт в SVG и PDF и нативное настольное приложение.
