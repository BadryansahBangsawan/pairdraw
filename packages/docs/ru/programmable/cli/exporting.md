# Экспорт

CLI экспортирует дизайн из терминала: растровые изображения, векторную графику, PDF, редактируемые презентации PowerPoint, диаграммы draw.io, отдельные документы `.fig`, код JSX, HTML или истории Storybook.

Приложение в сборках Pairdraw больше не предлагает экспорт в PowerPoint и draw.io; CLI по-прежнему записывает оба формата.

## Экспорт изображений

```sh
pairdraw export design.fig                           # PNG по умолчанию
pairdraw export design.fig -f jpg -s 2 -q 90        # JPG, масштаб 2×, качество 90
pairdraw export design.fig -f webp -s 3             # WEBP, масштаб 3×
pairdraw export design.fig -f svg                   # векторный SVG
pairdraw export design.fig -f pdf                   # PDF
pairdraw export design.fig -f pptx                  # редактируемый PowerPoint
pairdraw export design.fig -f drawio                # диаграмма draw.io
pairdraw export design.fig -f fig --page "Page 1"   # одна страница в отдельном .fig
pairdraw export design.fig -f fig --node 1:23        # один объект в отдельном .fig
pairdraw export design.fig -f html --css tailwind    # фрагмент HTML с классами Tailwind
```

Параметры:

- `-f` — формат: `png`, `jpg`, `webp`, `svg`, `pdf`, `pptx`, `drawio`, `jsx`, `tailwind-jsx`, `html`, `fig`, `storybook`
- `-s` — масштаб экспорта (по умолчанию `1`)
- `-q` — качество: `0`–`100` (только JPG и WEBP)
- `-o` — путь вывода
- `--page` — имя страницы
- `--node` — идентификатор объекта

## Политика замены шрифтов {#font-substitution-policy}

Для экспорта из файла в PNG, JPG, WEBP и PDF, а также для `pairdraw convert` можно выбрать, как обрабатывать отсутствующие или заменённые шрифты:

```sh
pairdraw export design.fig -f pdf --font-policy strict
pairdraw export design.fig -f png --font-policy warn
pairdraw export design.fig -f webp --font-policy allow
pairdraw convert design.pen --font-policy strict
```

- `warn` (по умолчанию) — сообщить о заменах и продолжить экспорт.
- `strict` — остановиться с ненулевым кодом выхода, если подготовка шрифтов не может точно найти запрошенные начертания.
- `allow` — экспортировать без дополнительной проверки точности шрифтов.

Сначала запустите [`pairdraw fonts`](./inspecting#font-diagnostics), чтобы посмотреть затронутые начертания. Подготовка к экспорту может использовать настроенных поставщиков шрифтов, поэтому её результат может отличаться от офлайн-диагностики файла.

`convert` загружает шрифты для файлов `.pen`, draw.io и Mermaid, которые хранят замысел компоновки, а не размеры: перед записью он раскладывает их заново, измеряя текст собственными шрифтами, поэтому `strict` останавливает команду до того, как что-либо записано. Блок-схема Mermaid (`.mmd` или `.mermaid`) раскладывается при чтении, а её текст измеряется шрифтами, которыми он рисуется.

Эта политика не действует при экспорте из запущенного приложения, а также для SVG, PowerPoint, JSX, HTML и `.fig`. Она проверяет подбор шрифтов, а не полное визуальное совпадение с Figma.

## Экспорт JSX

Экспорт в JSX со служебными классами Tailwind:

```sh
pairdraw export design.fig -f tailwind-jsx    # или: -f jsx --style tailwind
```

Результат:

```html
<div className="flex flex-col gap-4 p-6 bg-white rounded-xl">
  <p className="text-2xl font-bold text-[#1D1B20]">Card Title</p>
  <p className="text-sm text-[#49454F]">Description text</p>
</div>
```

Параметр `--style pairdraw` выбирает собственный формат JSX (см. [Рендерер JSX](../jsx-renderer)).

## Экспорт HTML

По умолчанию команда создаёт фрагмент HTML со встроенными стилями; вместо них можно использовать служебные классы Tailwind:

```sh
pairdraw export design.fig -f html
pairdraw export design.fig -f html --css tailwind
```

Параметр `--html standalone` создаёт HTML-документ, который можно открыть в браузере, со стилями сброса и обёрткой страницы. Этот формат предназначен для передачи дизайна и кода, а не для замены рендерера с точностью до пикселя:

```sh
pairdraw export design.fig -f html --html standalone --css inline
pairdraw export design.fig -f html --html standalone --css tailwind
pairdraw export design.fig -f html --html standalone --css tailwind --assets external
```

При автономном экспорте Tailwind компилируется во время экспорта и не зависит от браузерной среды Tailwind. `--assets external` записывает CSS и извлечённые изображения рядом с файлом HTML. `--fonts assets` вместе с внешними ресурсами находит шрифты текста SceneGraph через настроенных в Pairdraw поставщиков веб-шрифтов и создаёт локальные файлы `@font-face`.

Экспорт HTML записывает имя каждого слоя в атрибут `data-name`. `--no-layer-names` опускает имена, а `--layer-ids` добавляет ID каждого слоя как `data-pairdraw-node-id` для инструментов, которые связывают разметку с документом.

Экспорт HTML доступен в режиме файла.

### Токены в экспортированном коде

HTML и Tailwind JSX записывают свойства, привязанные к переменным, как дизайн-токены, из которых они взяты: заливка, привязанная к `Primary`, становится `background-color: var(--color-primary)`, а в Tailwind — `bg-primary` или `bg-(--name)` для токена вне пространств имён Tailwind. Слой, переключённый в другой режим, получает атрибут этого режима, например `data-theme="dark"`, чтобы токены разрешались так же, как их рисует холст.

Значение остаётся литералом там, где CSS не воспроизвёл бы его: слой больше не рисует значение переменной, токен безразмерный там, где нужна длина, или слой находится в режиме, который может выбрать только его собственное условие, например запрос `@media`. Автономный HTML включает таблицу стилей для использованных токенов; для фрагментов и JSX создайте её командой `pairdraw tokens` (см. ниже).

## Дизайн-токены

Запись переменных документа как пользовательских свойств CSS:

```sh
pairdraw tokens design.fig > tokens.css
pairdraw tokens design.fig --format tailwind > theme.css
pairdraw tokens design.fig --collection Theme --type COLOR
```

Режим по умолчанию каждой коллекции попадает в `:root`. Каждый другой режим переопределяет отличающиеся значения под своим условием: `[data-theme="dark"]` для режима Dark коллекции Theme или селектор либо запрос `@media`, который указывает режим. Псевдонимы остаются ссылками `var()` и объявляются заново в каждом режиме, который меняет их цель, поэтому переключение `data-theme` на любом элементе меняет стиль всего, что на нём построено.

```css
:root {
  --color-blue-500: #3b82f5;
  --color-primary: var(--color-blue-500);
}

/* Theme: Dark */
[data-theme='dark'] {
  --color-primary: var(--color-blue-300);
}
```

`--format tailwind` помещает токены с пространством имён Tailwind v4 (`--color-*`, `--spacing-*`, `--radius-*`, `--text-*`, …) в `@theme`, чтобы работали `bg-primary` и `rounded-card`, и добавляет `@custom-variant` для каждого режима, чтобы `dark:bg-surface` следовал тому же условию. Импортируйте файл после `@import "tailwindcss";`. Имена берутся из синтаксиса кода переменной, если он называет пользовательское свойство (`--x` или `var(--x)`), иначе — из имени и типа: цвет `Blue/500` становится `--color-blue-500`.

Токены, которые нельзя записать, например логические переменные или условие, которое не является селектором или запросом, перечисляются в stderr и пропускаются. Команда работает в режиме файла и с запущенным приложением.

### Дизайн-токены W3C

`--format dtcg` записывает переменные и стили в папку как [дизайн-токены W3C](https://www.designtokens.org/tr/2025.10/format/):

```sh
pairdraw tokens design.fig --format dtcg --out tokens
```

Каждый режим коллекции — отдельный файл, `Theme/Light.tokens.json` и `Theme/Dark.tokens.json`, в форме, которую Figma импортирует как режим: длины в `px`, время в `s`, логические значения как числа с пометкой `com.figma.type`, а псевдонимы на другую коллекцию называют её в `com.figma.aliasData`. Текстовые стили и стили эффектов становятся токенами типографики и теней в `styles.tokens.json` — отдельно, потому что импорт Figma отклоняет составные токены. `tokens.resolver.json` — резолвер DTCG, который переключает режимы каждой коллекции и накладывает остальное, для инструментов вроде Style Dictionary. Собственные поля Pairdraw, например единица `rem` токена, имя CSS, области применения или выражение `clamp()`, а также условие каждого режима, хранятся в `$extensions["dev.pairdraw"]`, поэтому экспорт читается обратно без потерь.

Импортируйте файлы токенов в документ инструментом `import_design_tokens`, передав путь и текст каждого файла:

```sh
pairdraw tool call import_design_tokens design.fig --args-file tokens.json --write
```

Он читает файлы по режимам, сгруппированные по папкам, резолвер с файлами, на которые он ссылается, или файл Tokens Studio с `$themes`. Коллекции и режимы с существующими именами, а также переменные и стили по имени обновляются; остальное добавляется, и ничего не удаляется. Результат перечисляет, что добавлено, обновлено и пропущено, с причиной каждого пропуска.

## Экспорт в Storybook

Команда создаёт по одному файлу CSF3 `.stories.ts` для каждого набора компонентов или компонента:

```sh
pairdraw export design.fig -f storybook                      # истории React в ./design-stories/
pairdraw export design.fig -f storybook --framework vue -o src/stories
pairdraw export design.fig -f storybook --css tailwind     # компоненты со стилями Tailwind
pairdraw export design.fig -f storybook --framework html --page "Components"
pairdraw export design.pen -f storybook -o src/stories --watch  # повторный экспорт при каждом сохранении
pairdraw export 'src/**/*.pen' -f storybook --beside --watch    # истории рядом с каждым дизайном
pairdraw export design.fig -f storybook --rules stories.json    # истории и заголовки по правилам
```

### Меньше историй на боковой панели

Каждый файл историй начинается с истории `Default` — варианта, который дизайн показывает в покое, со всеми элементами управления. Все остальные истории вариантов и состояний помечаются тегом `variant`, а каждый файл — тегами `pairdraw` и `page:<page>`, например `page:icons`. Фильтр боковой панели Storybook выбирает по этим тегам, а `.storybook/main.ts` может задать, что показывается по умолчанию, например одну историю на компонент и без страницы иконок:

```ts
const config: StorybookConfig = {
  // …
  tags: {
    variant: { defaultFilterSelection: 'exclude' },
    'page:icons': { excludeFromSidebar: true }
  }
}
```

### Истории и заголовки по правилам

То, что не умеют теги, например исключить компоненты или показать набор иконок галереей, решает файл правил. Экспорт читает `pairdraw.stories.json` из рабочей папки, если он там есть, или файл, указанный в `--rules`, — при слежении заново при каждом экспорте:

```json
{
  "rules": [
    { "match": "**", "title": "Design system/{page}/{name}" },
    { "match": "Icons/**", "stories": "gallery" },
    { "match": "**/_*", "stories": "none" }
  ]
}
```

Правило применяется к каждому файлу историй, путь `<page>/<name>` которого совпадает с его шаблоном, по именам в документе: имени страницы и имени набора компонентов или компонента либо префиксу компонентов с именами через косую черту, например `Icons/icon`. Все подходящие правила применяются по порядку, поэтому более позднее правило переопределяет более раннее, каждое поле отдельно. `generate: false` оставляет статические истории при экспорте Vue или React там, где был бы создан компонент, например для набора иконок. `stories` может быть `variants` — история на каждый вариант или состояние, как без правил; `single` — только история `Default`; `gallery` — `Default` и история `Gallery`, которая выкладывает все варианты с их именами, для статических историй; или `none` — файл не создаётся. `title` — заголовок файла, в котором подставляются `{document}`, `{page}`, `{name}` и `{path}` (заголовок, который был бы у файла); совпавшие заголовки разводятся так же, как всегда. Правила сопоставляются с именами в документе, а не с переименованным заголовком, поэтому переименование файла не меняет применяемые к нему правила.

### Дизайн рядом с историями

Храните файл дизайна компонента в папке самого компонента и экспортируйте с `--beside`: истории каждого документа, изображения дизайна и манифест `.pairdraw-stories.json` попадут в папку этого документа, рядом с кодом компонента. Шаблон `stories` в `.storybook/main.ts`, например `../src/**/*.stories.ts`, подхватит их без дополнительной настройки.

Можно передать несколько документов или шаблон в кавычках, например `'src/**/*.pen'`, который Pairdraw раскрывает сам (нужен Node.js 22 или новее). Для нескольких документов необходим `--beside` или `--output`; `--page` работает только с одним документом. Документы экспортируются по очереди; если один не удалось экспортировать, остальные всё равно будут обработаны, а команда завершится с ошибкой. `--watch` следит за всеми найденными документами; документ, созданный после запуска слежения, потребует повторного запуска.

Заголовки историй строятся из имени файла документа, а затем страницы, если компоненты есть больше чем на одной странице: `pricing.fig` даёт `pricing/Plan picker`, поэтому истории документов, экспортированных вместе, не смешиваются. Каждый вариант набора компонентов становится историей, а его свойства вариантов — элементами управления `select`, поэтому переключение элемента показывает соответствующий вариант. Набор с поведением получает вместо этого собственные свойства элемента управления: у Switch или Checkbox есть логическое `checked`, у Toggle — `pressed`, у Collapsible — `open`, и `disabled`, если набор рисует отключённое состояние; наведение, нажатие и фокус остаются отдельными историями. Отдельные компоненты с именами через косую черту, например `Button/Primary` и `Button/Secondary`, собираются в один файл `Button` с элементом управления `Variant`. Если в дизайне нет варианта для выбранной комбинации, Storybook выдаст ошибку с именем, а не покажет другой вариант.

Истории отображают компонент как HTML со встроенными стилями, как `-f html`, поэтому среда выполнения Pairdraw не нужна; `--framework` (`react`, `vue` или `html`) меняет только обёртку и импорт `Meta`/`StoryObj` из `@storybook/react-vite`, `@storybook/vue3-vite` или `@storybook/html-vite`. Текст использует семейства шрифтов документа: экспорт загружает их файлы у тех же поставщиков веб-шрифтов, что использует редактор, в `pairdraw/<document>/` вместе с `fonts.css`, который импортирует каждый файл историй, поэтому истории сразу рисуются этими шрифтами, а не запасными. Туда же попадают переменные дизайна документа — как пользовательские свойства в `tokens.css`, который импортирует каждый файл историй, поэтому стили, привязанные к переменным, разрешаются так же, как их рисует дизайн. Семейство, которого нет ни у одного поставщика, например Menlo, заменяется шрифтами браузера, о чём экспорт предупреждает; `--fonts none` не поставляет файлы шрифтов. Статические истории пока не экспортируют текстовые и логические свойства и свойства замены экземпляра.

С `--framework vue` или `--framework react` каждый набор компонентов и отдельный компонент становится настоящим компонентом — `<Name>.vue` или `<Name>.tsx` с `<Name>.module.css` (с `--css tailwind` — служебные классы Tailwind в разметке, а состояния как варианты вроде `data-[state=checked]:`, для проекта, который собирает Tailwind v4), кроме компонентов с именами через косую черту, собранных в один файл, и тех, для которых правило задаёт `"generate": false`: они сохраняют статические истории. Компонент без поведения состоит из собственных элементов дизайна: его корень — элемент, который рисует дизайн, `div` для фрейма, и он принимает свойства корневого элемента, например `onClick` и `class`. Его свойства вариантов — это пропсы, которые он задаёт как атрибуты `data-*`, поэтому вариант `State=hover` — такой же пропс, как остальные; логические свойства — логические пропсы, которые показывают или скрывают привязанные к ним слои; а свойства слотов — содержимое, которое он показывает вместо содержимого дизайна: именованный `<slot>` во Vue и пропс `ReactNode` в React, с содержимым дизайна по умолчанию. Компонент, поведение которого — Button, Switch, Checkbox, Toggle, Collapsible, Tabs, Radio group, Toggle group, Accordion, Slider, Progress, Number field, Text field или Textarea, строится на Reka UI или на пакете `radix-ui` от Radix UI, а его интерактивные состояния, например наведение и отключение, становятся настоящими стилями `:hover` и `data-disabled`. Его варианты компилируются в таблицу стилей с ключами по состояниям, которые задают Reka и Radix (`data-state`, `data-disabled`, наведение и фокус), а каждое другое свойство варианта — пропс, который компонент задаёт как атрибут `data-*`. Во Vue его значение — `v-model`, например `checked` или `open`; в React компонент принимает пропсы корня Radix, например `checked`, `defaultChecked` и `onCheckedChange`. Его текстовые свойства — строковые пропсы со словами дизайна по умолчанию, которые рисуют привязанные к ним слои, с текстовым элементом управления в историях.

Tabs принимают открытую вкладку как `value` (`v-model:value` или `defaultValue` и `onValueChange` в React), названную по словам каждого триггера в виде слага, например `account` или `password`, и начинают с первой; каждый триггер и его панель — части `Tabs` из Reka или Radix вокруг слоёв дизайна, каждый триггер рисуется как остальные триггеры дизайна и принимает вид первого триггера, пока его вкладка активна, а истории получают элемент управления `select` и историю для каждой вкладки. Radio group, Toggle group или Accordion создают два компонента: группу, которая выбирает один элемент тем же способом, начиная с элемента, который дизайн рисует включённым, и `<Group>Item` из набора компонентов её элементов, построенный как примитив элемента группы (`RadioGroupItem`, `ToggleGroupItem` или `AccordionItem` с триггером в заголовке) и принимающий `value`, которое он представляет. Группа использует его по одному разу на каждый элемент в слоте элементов, со значением каждого элемента, названным по его свойству подписи или по словам, и с его текстовыми значениями. Slider, Progress или Number field привязывают своё число как `value` (`v-model:value` или `defaultValue` в React, список — для слайдера Radix) в диапазоне, заданном поведением, начиная с того значения, что в дизайне; диапазон и бегунок слайдера и индикатор прогресса теряют позицию, в которой их рисует дизайн, потому что её задаёт значение, а истории получают элемент управления диапазоном и историю на каждом краю. Text field или Textarea рисуют свой текстовый слой как нативный `input` или `textarea`, привязанный к `value`, который в React принимает пропсы компонента; если дизайн рисует поле заполненным и пустым, слова пустого поля становятся заполнителем, а его вид — видом заполнителя, и заполненный вид показывается, пока в поле есть текст. Числовое поле Reka UI рисует ввод и кнопки шага во Vue; в Radix его нет, поэтому в React это нативный числовой ввод, кнопки которого меняют значение на шаг и который при уходе из поля возвращается в свой диапазон. Фокус на бегунке слайдера или вводе поля рисует состояние фокуса элемента управления. Radio создаётся только как элемент группы; Toggle или Collapsible, используемые отдельно, по-прежнему становятся собственными компонентами.

Внутри созданного компонента экземпляр другого компонента, созданного тем же экспортом, использует этот компонент, а не рисует свои слои: `<Switch>`, импортированный из `./Switch.vue` или `./Switch`, с вариантом, текстом и значением `disabled`, которые показывает экземпляр. Элемент управления, который дизайн рисует включённым, например включённый переключатель, начинает включённым и остаётся рабочим: локальный `ref`, привязанный через `v-model` во Vue, `defaultChecked` в React. Родитель только размещает его, поэтому элемент управления сохраняет собственный вид и стили состояний. Компонент использует только тот экземпляр, который рисуется ровно как его вариант, не считая значений свойств и места, куда его ставит родитель; экземпляр с изменённым текстом, который не задаёт ни одно свойство, собственной заливкой или другими изменениями рисует свои слои, поэтому история сохраняет то, что показывает дизайн. Экземпляры компонентов, которые не экспортируются или экспортируются только как статические истории, рисуются как раньше. Свойство варианта, значение которого по умолчанию документ оставил пустым, начинает с варианта по умолчанию — того, что в левом верхнем углу набора, — с которого открываются его истории. Иконка, вставленная из набора, если её контуры не редактировались, становится компонентом Iconify — `<Icon icon="lucide:bell">` из `@iconify/vue` или `@iconify/react`, который загружает иконку при показе.

Слой с шейдерной заливкой воспроизводит шейдер за своим содержимым с помощью `<Shader>` из библиотеки `shaders` (`shaders/vue` или `shaders/react`), где каждый эффект — дочерний элемент с пропсами пресета и отключённой телеметрией (`disableTelemetry`); браузеры без WebGPU ничего на его месте не показывают.

Истории отображают компонент, а функция play нажимает элемент управления и проверяет его состояние, поэтому в проекте Storybook нужно установить `reka-ui` или `radix-ui`, а также `@iconify/vue` или `@iconify/react`, если компоненты содержат иконки, и `shaders`, если слои залиты шейдерами.

В историях есть записи `parameters.design` для [`@storybook/addon-designs`](https://github.com/storybookjs/addon-designs):

- **Pairdraw:** если документ находится внутри текущей папки, это [ссылка `pairdraw://`](../index#url-scheme), которая открывает документ в настольном приложении и выделяет вариант или его набор компонентов, когда другой слой носит то же имя, что и вариант. Схема обращается к слоям по имени, поэтому история, у которой имена варианта и компонента повторяются у других слоёв, ссылки не получает.
- **Design:** PNG варианта в масштабе 2×, записанный в `<Name>.design/` рядом с историей и подключённый через `new URL(…, import.meta.url)`, чтобы Vite включил его в сборку. Скопируйте параметр в историю собственного компонента, чтобы сравнить реализацию с дизайном. `--no-design-images` пропускает отрисовку; замена шрифтов подчиняется `--font-policy`, как при растровом экспорте.

`-o` задаёт папку вывода. Манифест `.pairdraw-stories.json` в ней записывает, какой документ (путь относительно папки вывода) и какая страница создали каждую историю и изображение дизайна; сохраняйте его в репозитории вместе с историями. Экспорт заменяет файлы, созданные предыдущим экспортом того же документа в этой папке, включая файлы удалённых или переименованных компонентов; с `--page` — только файлы этой страницы. Прежде чем что-либо менять, команда откажется перезаписывать любой другой файл: написанную вручную историю, историю другого документа или постороннее изображение. Если при экспорте одной страницы имена файлов сместились на истории другой страницы, потребуется полный экспорт. Без манифеста существующие истории считаются чужими, поэтому перед повторным экспортом удалите их. `--watch` оставляет команду запущенной и повторяет экспорт при каждом сохранении документа, так что горячая перезагрузка Storybook следует за дизайном; если сохранённый файл прочитать не удалось, команда сообщает об этом и продолжает следить. Отсутствующая `--page` или замена шрифта при `--font-policy strict` по-прежнему завершают команду.

## Экспорт из запущенного приложения

Не указывайте файл, чтобы экспортировать из запущенного приложения:

```sh
pairdraw export -f png                       # выделение в активном документе
pairdraw export --page "Components" -f png   # все слои страницы
pairdraw export --node 1:23 -f png           # один слой на любой странице
```

`--page` принимает имя страницы, а `--page-id` — ID страницы из `pairdraw documents list`; любой из параметров экспортирует страницу, не переключая на неё приложение. Добавьте `--document-id`, чтобы экспортировать из документа, который не является активным.

В режиме запущенного приложения поддерживаются PNG, JPG, WEBP, SVG и PDF. Для PowerPoint, JSX, HTML, Storybook и `.fig` нужно указать файл. Экспорт миниатюр в режиме файла пока не поддерживается.
